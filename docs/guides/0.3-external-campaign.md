finish the 0.3 research campaign; it does not authorize spending, credential use, remote workflow
dispatch, publication, or release creation.

## Authorization inputs required

Before a live command is run, record all of the following in the task handoff:

1. Maximum provider spend and the time window covered by that ceiling.
2. The three allowed providers and confirmation that they resolve to three distinct backend
   families.
3. Which credential environment-variable names may be used. Examples of names are
   `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, and `MIMO_API_KEY`; never put their values in a manifest.
4. Approved isolated-home paths, supplied through `UAEK_PROVIDER_A_HOME`,
   `UAEK_PROVIDER_B_HOME`, and `UAEK_PROVIDER_C_HOME`.
5. The owner-approved replacement baseline and its immutable `source_ref`.
6. Separate authorization for remote CI dispatch, push/release actions, and PyPI publication.

## Authorized campaign commands

After approval, create `benchmarks/manifests/evidence-campaign.external.json` from the committed CI
example. It must define three providers with different `backend_family` values, `sample_count: 3`,
isolated `provider_home` paths, and an output directory under
`benchmarks/evidence/external/campaign`. The commands may read approved credentials from the
process environment; the JSON must never contain credential fields or values.
Provider-derived and explicit sample IDs must be safe file-name slugs beginning with an ASCII
letter or digit and containing only letters, digits, `.`, `_`, or `-`.

Resolve the path and validate before any provider execution:

```bash
export UAEK_EXTERNAL_CAMPAIGN_MANIFEST=benchmarks/manifests/evidence-campaign.external.json
.venv/bin/uaek evidence campaign validate "$UAEK_EXTERNAL_CAMPAIGN_MANIFEST" --output -
.venv/bin/uaek evidence campaign run "$UAEK_EXTERNAL_CAMPAIGN_MANIFEST" \
  --dry-run --output /tmp/uaek-external-sample-plan.json
```

Inspect the plan: it must contain nine samples total, three for each of three distinct backend
families. Only after spend and credential approval, execute once:

```bash
.venv/bin/uaek evidence campaign run "$UAEK_EXTERNAL_CAMPAIGN_MANIFEST" \
  --output benchmarks/evidence/external/campaign-run.json
.venv/bin/uaek evidence campaign aggregate \
  benchmarks/evidence/external/campaign/*.json \
  --output benchmarks/evidence/external/campaign-summary.json
```

If a provider fails after some immutable samples have been written, inspect
`benchmarks/evidence/external/campaign/.campaign-state` and rerun the same manifest with
`--resume`. UAEK reuses an existing sample only after validating both its artifact contract and
its complete campaign identity; a mismatched or corrupt artifact stops the run.

Cost collection writes at least five real records per cohort to
`benchmarks/evidence/external/cost/cost-ledger.json`; session collection writes 100 immutable JSON
files under `benchmarks/evidence/external/sessions`. Validate them before audit:

```bash
.venv/bin/uaek evidence cost validate \
  benchmarks/evidence/external/cost/cost-ledger.json --output -
.venv/bin/uaek evidence cost aggregate \
  benchmarks/evidence/external/cost/cost-ledger.json \
  --output benchmarks/evidence/external/cost/cost-summary.json
for artifact in benchmarks/evidence/external/sessions/*.json; do
  .venv/bin/uaek evidence session validate "$artifact" --output /tmp/session-validation.json
done
.venv/bin/uaek evidence session aggregate \
  benchmarks/evidence/external/sessions/*.json \
  --output benchmarks/evidence/external/session-summary.json
.venv/bin/uaek evidence baseline validate \
  benchmarks/evidence/external/baseline.json --output -
.venv/bin/uaek audit --iterations 1 \
  --baseline benchmarks/evidence/external/baseline.json \
  --evidence-root benchmarks/evidence/external \
  --output benchmarks/evidence/external/audit.json
```

Archive raw artifacts, summaries, the exact commit SHA, and the remote run URL. Publication remains
a separate final action and requires explicit approval plus the configured PyPI credential; a
successful local or remote audit is not publication authorization.

## Completion check

The external campaign is complete only when the summary shows three real backend families, every
family has three samples, each cost cohort has five real sessions, session aggregation reports 100
live sessions, the baseline status is `provided`, and an independent run is archived. Otherwise,
report the exact remaining counts from the table above and keep the 0.3 external gate blocked.

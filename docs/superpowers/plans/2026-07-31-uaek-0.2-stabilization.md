# UAEK 0.2 Stabilization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert the current uncommitted UAEK runtime expansion into a tested, documented, release-gated 0.2 development baseline while separating externally blocked evidence work.

**Architecture:** Preserve the existing three-entrypoint design (CLI, HTTP API, MCP) over shared effort, workflow, verification, memory, and security services. Stabilization proceeds from domain behavior tests outward to entrypoint contracts, then aligns local and remote quality gates and evidence documents.

**Tech Stack:** Python 3.11+, pytest/pytest-cov, Ruff, Mypy, Click, PyYAML, stdlib HTTP/JSON-RPC, setuptools/build, GitHub Actions.

## Global Constraints

- Preserve all pre-existing user changes; do not reset, delete, or rewrite unrelated files.
- Use test-first changes for every production behavior fix.
- Keep optional ChromaDB, sentence-transformers, and Z3 integrations optional and lazily imported.
- Do not publish to PyPI, push Git branches, or invoke credentialed live providers without explicit authorization.
- Every reported metric must retain an evidence rung and an explicit caveat.
